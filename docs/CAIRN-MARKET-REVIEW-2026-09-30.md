# Cairn market check · 30 September 2026

This is a review of public vendor descriptions, not hands-on comparative testing. The category is crowded: [CleanMyMac](https://macpaw.com/support/cleanmymac/knowledgebase/smart-care) combines guided cleanup tasks; [DevCleaner](https://devcleaner.app/) addresses developer artifacts and documents its [evidence records](https://devcleaner.app/docs/evidence-and-records); [DaisyDisk](https://web.daisydiskapp.com/) makes visual space exploration its core; [Storage Studio](https://storagestudio.us/features) advertises capacity history, targets and external SSD workflows; and [Storage Link Manager](https://apps.apple.com/us/app/storage-link-manager/id6792249586?mt=12) offers an external-storage workflow. Cairn should not claim to be the first cleaner, the only developer cleaner, or the only SSD manager.

The strongest opening is an honest **capacity decision and recovery trail**: show where measurable space changed, which proposed action is actually supported, what was selected, whether available capacity changed on the same volume, and how to recover or investigate an interrupted step. This should work across browser, app, creator and developer data, with application-specific guardrails. This position must be validated with real users; it is not yet a market advantage proved by download or retention data.

Priority order for a beta:

1. Finish the complete scan → review → action → measured receipt → recovery journey on disposable and then explicitly reviewed real data. Keep estimates separate from capacity gains and do not auto-select tool-owned/live caches.
2. Certify one narrow, genuinely useful immediate-reclaim action with exact target, writer and interruption proof. The isolated npm verification spike is insufficient to enable it; see [npm adapter gate](../artifacts/storage-control/npm-adapter/IMPLEMENTATION-GATE.md).
3. Test one supported external-SSD tool-location adapter on physical disposable storage with drive identity, missing-drive startup and rollback. The current verified export remains a copy, not managed relocation.
4. Keep reserve monitoring alert-only until sustained energy, sleep/wake and notification tests pass. Add selective rules only after per-rule review, limits, history and independent safety review.
5. Make public update/payment promises only after their end-to-end infrastructure and the paid feature boundary are real. The current build does not advertise broad tool cleanup for purchase.

The first-run promise should stay simple: “See what changed. Make a reviewed choice. Verify the result.” A large dashboard of unverifiable savings would weaken that position.
